# ConvNeXts
In this repo I try to investigate different aspects of convnext and how they compare to traditional CNNs and vision transofrmers

## Inference efficiency

Run `notebooks/02_inference_efficiency.ipynb` from top to bottom. It compares
ConvNeXt-Tiny, Swin-Tiny and ResNet-50 at batch sizes 1 and 32 with 224×224
FP32 inputs. By default it uses random weights and 37 output classes: this is
an architecture-speed benchmark, not an accuracy evaluation. Set `PRETRAINED`
if pretrained weights are desired (requires a download).

Each run writes to `results/inference_efficiency/<UTC timestamp>/`
(ignored by Git). Charts are generated by the notebook for use in the article;
no generated images are committed to the repository:

- `inference_results.json`: raw repeat-average times, all settings and environment metadata.
- `inference_summary.csv`: one scalar summary row per model and batch size.
- `inference_batch_1.png` and `inference_batch_32.png`: GFLOPs/image, batch latency
  and throughput, with no titles or explanatory text inside the graphs.

Timings exclude transfers, preprocessing and FLOP counting. Each model warms up
before five repeats of 100 forward passes. CPU, CUDA and MPS use the same
wall-clock method, with accelerator synchronization at the start and end of
each repeat. Latency is the median of the repeat-average batch times; throughput
is batch size divided by that value. Whiskers show the min–max range across
repeat averages, not confidence intervals or per-request tail latency. Batch-32
latency is time for the whole batch, not single-image response time.

FLOPs are counted separately for one forward batch using PyTorch's registered
operator formulas, then normalized per image. Multiply-add counts as two FLOPs;
unsupported operators may be omitted. These counts are not directly comparable
to sources that count one MAC as one operation. Inputs stay on the device and
models run in evaluation/inference mode without compilation or autocast.
For publication, record the exact hardware model (the automatically detected
processor string may be generic on macOS) and keep background load low. If batch
32 does not fit, choose a smaller common batch size for all models. The notebook
saves partial numerical results after each completed configuration and lets
errors surface rather than silently omitting failed measurements.
